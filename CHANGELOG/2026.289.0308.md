# 2026.289.0308 — feat(skills): the 2 skills and 6 agent definitions move to `.agents/`; the nodes keep the routing (L10, W2)

## Summary

`layer-charly-internals-extra` owns eight `skill:`-kind nodes: the two real skills `strict-policy` and
`vm-spec`, plus **six that are discriminated by `type: agent`** — `check-bed-runner`, `deploy-verifier`,
`layer-validator`, `pr-validator`, `root-cause-analyzer`, `testing-validator`. This change moves all
eight bodies out of `charly.yml` and into the file each entity owns, under the settled D8 shape:

- a skill → `.agents/skills/<name>/SKILL.md`
- an `agent`-type node → `.agents/agents/<name>.md`

`charly.yml` keeps the routing metadata its consumers read — `name`, `family`, `owner`, and, where they
exist, `type`, `model`, `triggers` — and drops `description:` and `content:` on all eight. That is
**16 keys on 8 nodes**, and nothing else in the manifest moves. `AGENTS.md` and `README.md` are
retargeted per D5 to name the skills rather than point at the entities that used to hold their prose.

The move is invisible in the published corpus, which is the property the whole relocation rests on — and
this repo is where that claim is hardest: it is the first repo whose **agents** move, so both artifact
trees are in one diff.

**The target set is keyed on `type: agent`, never on the node-name suffix.** The six agent nodes are
named `*-agent`, not `*-skill`, so every earlier leg's `*-skill:`-keyed enumeration missed them, which is
why `plugin-marketplace#34`'s live instance (`pod-charly-automation#25`) was found only by running the
verb and reading where it wrote. Enumerated on the head:
