# 2026.294.2355 — feat(pr-validator): the COORD check reads WAITING/HOLDING, with the dated legacy carve-out

## Summary

The `charly/pr-validator` agent's own coordination check named `BLOCKS` — the same token its verdict
vocabulary uses for "this finding blocks the merge". A coordination comment announcing a dependency
therefore read like a verdict rejecting the PR, inside the one document that defines the rulebook the
validator enforces.

This repo owns the AUTHORED SOURCE of the `pr-validator` agent, so the labels are renamed here, at
the source. `BLOCKS` splits by direction — `WAITING` (the blocked side) / `HOLDING` (the blocking
side) — and `UNBLOCKS` becomes `CLEARED`, so a comment's first line states which side is speaking.
The closed set across the org becomes nine labels, sharing no token with the verdict vocabulary:

    CLAIM · OWNING · HANDING OVER · TAKING OVER · WAITING · HOLDING · CLEARED · STATUS · RESOLVED

The check also states the closed set in full: a coordination comment opens with one of the nine labels
and nothing else, and a comment opening with any other word is not a coordination comment, so the check
does not count it. There is no exception and no grace period — a thread that was answered under the old
labels is answered again in the new grammar.

**What changed in this round.** The first version of this PR carried a dated grandfather clause: a
coordination comment opening with a legacy label would be honoured when it was created strictly before
`2026-10-24T00:00:00Z`. Two of the three fresh validators on this PR blocked it — a dated read path for
the old labels is a legacy path surviving in the shipped rulebook, and the cutover policy sanctions no
grace period — and the clause contradicted the sentence beside it. The clause is GONE in this commit:
the grammar is a pure hard cutover, nine labels, no exception, no date.

One file changes — `.agents/agents/pr-validator.md`, in two places:

| Site | What it now says |
|---|---|
| the check-19 body (the human-readable twin of the validator's COORD check) | a `WAITING`/`HOLDING` comment must exist on both threads, and a coordination comment opens with one of the nine closed-set labels and nothing else |
| the checklist summary line for check 19 | `coordination (WAITING/HOLDING on both threads; footer order)` |

**This is one leg of a six-repo cutover, not the whole of it.** The contract being cut over — the
coordination grammar — lives in six repos, and the producer-first pin contract forces the order: a pin
may only point at a MERGED ref, so the authored sources land first, the corpus that is GENERATED from
their tags follows, and the umbrella's gitlinks follow the corpus. That is the DECOMPOSITION axis of the
cutover policy — one contract, ordered units, scope never narrowed — and the tracking issue
`opencharly/opencharly#567` stays open until the last unit lands.
